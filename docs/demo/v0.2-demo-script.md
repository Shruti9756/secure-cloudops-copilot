# SecureCloudOps Copilot — V0.2 Demo Script

> Status: release walkthrough for V0.2.
>
> Target duration: 3–4 minutes.
>
> Use synthetic demonstration data only. Never show a password, JWT, AWS credential, or presigned S3 URL.

## Purpose

Use this walkthrough to explain how V0.2 turns the V0.1 local RAG MVP into a multi-tenant, authorization-aware application. The required visual evidence is stored in `docs/release/screenshots/v0.2/`.

## 1. Introduce the security model

Say:

> SecureCloudOps Copilot investigates incidents from approved engineering knowledge. V0.2 adds Cognito authentication and application-side authorization: a signed-in user’s Cognito subject is mapped to a PostgreSQL membership, organization, workspace, and role before the API retrieves evidence or allows document operations.

Point out that `X-Workspace-Slug` is only a workspace selector. It is not proof of access.

## 2. Show an authorized grounded answer

Sign in as the NimbusCart administrator and ask:

```text
Why did checkout latency increase after the deployment?
```

Show that the answer:

- identifies the active NimbusCart workspace and administrator role;
- cites retrieved evidence;
- reports structured-output, citation, and safety validation as passed; and
- shows whether Redis served a cache hit or miss.

Explain:

> The model returns a constrained JSON answer and citations. The API validates that schema, then verifies every citation against the retrieved source identifiers before returning it.

## 3. Show tenant and role isolation

Sign in as the SkyForge engineer. Ask:

```text
What should I inspect when SKYFORGE-ONLY-INCIDENT-2026 appears?
```

Show that the answer cites only `skyforge-isolation.md`, and that the engineer cannot upload or update documents.

Explain:

> Retrieval is filtered by the caller’s organization and document visibility. The UI reflects the role, but the API independently enforces the same rules.

## 4. Show cross-workspace denial and audit trail

While signed in as the NimbusCart administrator, make a request that selects the SkyForge workspace. Show the `404` response, then show its matching `authorization.workspace_access` audit event.

Say:

> The API returns a privacy-preserving not-found response rather than revealing whether another workspace exists. The audit record keeps the authenticated actor, request ID, permission, and denial status, but never stores a token or raw question.

## 5. Show safe redacted document download

As an authorized NimbusCart administrator, use **Get secure link** for a document stored in S3. Show the UI confirmation and expiry information only—do not reveal or copy the generated URL.

Say:

> S3 stores only already-redacted extracted text. After document, organization, and role checks, the API creates a short-lived link pinned to the stored object version. The link is a temporary bearer capability, so it is never logged, committed, or shown in the demo.

## 6. Close with verification

Show the V0.2 release checklist and summarize:

- 232 API tests pass in the default suite;
- web lint and production build pass;
- Terraform validates with no infrastructure drift; and
- the captured screenshots document the principal authentication, isolation, audit, and quality flows.

Finish with:

> V0.2 is a secure local-development baseline, not a production deployment. The next release focuses on reliability, measurable RAG quality, and operational resilience.
